and the Claude chat conversations used for project management.

**What this is not:** a record of environment or deployment state. That rots
silently. Every claim about state below names the command that produces it —
run the command. Anything marked **[verify]** was not confirmed. **If this
file and the repo disagree, the repo wins.**

Mirrored publicly at
[ThePYPGuy/thebrainbureau-docs](https://github.com/ThePYPGuy/thebrainbureau-docs)
so chat sessions can read it. That is a **mirror, not a second source of
truth** — it is generated by `npm run docs:sync` and never edited by hand.

**This file is public.** Project refs, deployment names and machine-specific
paths live in `docs/local/environment.md`, which the sync holds back. Not
because any of it is secret, but because publishing it helps nobody and public
history is permanent. Read that file for any path or identifier named below.

**Provenance.** Two kinds of claim live here, and they are not equally good.

`--prod`), `git log`, `git status`, `git worktree list`, `git rev-list`,

## 3. Overlap risks — READ BEFORE ASSIGNING WORK

- **A session committing to `main` mid-task sweeps up other sessions'
  uncommitted files.** `8839d38` is titled for the `deploy:check` fix and also
  carries Doc Manager's in-progress `CLAUDE.md` edits, committed by a session
  that had not written them. Commit by path, never `git add -A`, and read
  `git status` first — another session's work may be sitting in the tree.
- **Renormalising line endings rewrites the working tree and discards
  uncommitted edits.** `f0563c2` added `.gitattributes` with `* text=auto
  eol=lf`, which is correct and wanted. Applying it rewrote tracked files from
  the index, and **Doc Manager's uncommitted `STATUS.md` and
  `scripts/docs-sync.mjs` changes were silently lost** — no error, no conflict,
  the files simply reverted. They had to be written again. Commit or stash
  before anyone renormalises.
- **Prime Directive is a Case File activity, and its branch does not contain
  the Case File skin.** Verified: `main` holds commits the branch lacks,
  including `735c6bb`, which *is* the skin. The branch cannot render as
  designed until `main` merges into it again.
- **`npm run doctor` does not exist on `operation-prime-directive`.** The
  script arrived in `d446fb4`, after that branch last took `main`. Running it
  from the worktree fails. Verified: `grep -c doctor package.json` returns 0.
- **Shared platform files are not Operation files.** `app/globals.css`,
  `lib/skins.ts` and the engine render *every* activity. A change made for one
  Operation changes Zero Hour, which is live. Operation branches carry content;
  shared-file edits are platform tasks.
- **`package.json` `"import"` is a hardcoded list, not a glob** — every new
  activity conflicts here on merge. Resolution is always "keep both sides".
  The previously-predicted `import:curriculum` conflict has **already been
  resolved** by merge `46d7037`. Expect the next one anyway.
- **`bb49a62` on the branch duplicates `5fda3d3` on `main`** — same message,
  "Homepage: say what the site actually is now". The duplicate is verified;
  that it is residue from the wrong-branch incident in `CLAUDE.md` is inference
  — nobody has confirmed it. Either way, likely to conflict on merge.
- **Skin tokens must stay namespaced `--skin-font-*`.** `app/layout.tsx` binds
  `--font-display` / `--font-body` on `<html>` for the Bureau light face.
- **Migration ordering:** entitlement changes need **code first**; schema
  changes need **migration first**. Backwards fails silently.

## 5. Environment

`npm run doctor` — run 2026-08-25: **no failures, 2 warnings.**

```
WARN  uv                      not on PATH (only needed for image generation)
WARN  tools/google-image-gen  not present
```

Both expected — the image pipeline lives outside the repo.

**What doctor does not assert:** secret *shape*, never identity.
`sb_secret_… len 41` reads identically before and after a key rotation. It
catches an empty, truncated or `[SENSITIVE]` key. It cannot tell you the key
is the *right* one. Do not cite a green secrets block as proof of a rotation.

**Paths and identifiers** — repo locations, worktrees, the Supabase project
ref, the Vercel project, and Maciej's folders outside the repo — are in
`docs/local/environment.md`, not here. `git worktree list` and `npm run doctor`
outrank that file.

The conventions that go with them, which are worth repeating in public:

- The platform repo is in **WSL, not the Windows filesystem**. A session once
  lost an hour searching `C:\` for it.
- From a Windows shell: `wsl -e bash -ic '...'` — **`-ic`, not `-lc`**, or
  `npx` and `tsc` resolve to the Windows binaries.
- Style templates: `content/styles/` in the repo is authoritative.
- `.env.local` points at **local** Supabase (`http://127.0.0.1`) and takes the
  *local* secret key. Production keys belong in Vercel only, and the secret key
  is the only credential that can read answer keys.
