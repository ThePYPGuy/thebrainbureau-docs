# Operation Tailwind — the twelve, and what has no code

**§9 of the build instructions has twelve items. Item 9 is wholly deferred and
item 6 is half deferred, so a complete build is ELEVEN of twelve.** Item 6 is
the trap on this list: *board state survives logout/login (both modes)* does not
read as a class-mode line, so anyone who tests solo would tick something
half-tested.

**Nothing below is a status.** Each line names the check, because which of these
is true changes hourly and a written answer would be stale before it was read.

## The three that have no code at all

These are BUILDS, not fixes, and they are what the acceptance checklist depends
on rather than what it tests.

**Board state has a table and no writer.** Migration 37 creates
`agent_board_state`, indexes it and gives it RLS. Check whether anything writes
it: `grep -rn board_state lib/server/*.ts`. This is the same defect that left
`agent_findings` unwritten in the same migration — **a table nobody writes to is
not a feature, and it fails silently by looking exactly like a feature.**

**No photo credits surface.** Item 11 wants credits where photos render. Check:
`grep -rni "credit" lib components app supabase`. The licensed photographs are
a licence obligation, not a nicety.

**Nothing regenerates the ZIP, and there is no per-operation overview page.**
Item 10 wants an overview page with five per-file downloads and a ZIP
regenerated by the deploy step. Check: `grep -rn zip scripts/*.ts package.json`
and `find app -ipath "*operation*" -name page.tsx`. The private bucket and the
entitlement route exist; the page and the regeneration step do not.

## The eight that are code, and how each is proven

| # | Item | The proof it needs |
|---|---|---|
| 1 | `situation-room` worn | `npm run skins` reports it worn, not merely legal |
| 2 | Nine items in any order; 2 gated on 1 only | Play, not unit tests |
| 3 | 7 singles + either 6/7 lights the console | **Needs a finding to have actually posted** |
| 4 | Exactly two candidates eliminated pre-console | Count at the console, not in the data |
| 5 | 479 wrong combinations refused identically | **Must include a case that is ACCEPTED** |
| 7 | Every number matches the fixed-facts table | Read against the clue documents, the one source of truth |
| 8 | Screen insets and printed MAPs A/B agree | Same answer from either, not similar images |
| 12 | Evidence items / findings; no phase, lock, task | Read the rendered strings |

**Item 5 is the one that can pass while broken.** A console that refuses
EVERYTHING refuses all 479, so the test must contain a combination that must be
accepted. Item 3 has the same shape from the other side: the gate has so far
only been exercised at zero findings, where refusing is correct, and *refusing
when it should refuse is half a test.*
